# L-08 · Unit register

Source: UI/UX Specification v1.0, Part B. Module M-5 (product.md §6).

## Meta

| | |
|---|---|
| ROUTE | `/units` |
| PURPOSE | The list of everything owned, and the way in to a unit's full history. |

## Components and interactions

| ID | Type | Content · what happens |
|---|---|---|
| L08-TBL-UNITS | Data table | Columns: Unit · Property · Type · Rent · Current tenant · Status. Row click → L-09. |
| L08-CHP-STATUS | Status chip | Occupied (success) · Vacant (neutral) · Notice period (warning) |
| L08-BTN-ADDUNIT | Primary button | "Add unit" → inline form: property, unit number, type, rent, deposit |
| L08-BTN-PRINTQR | Secondary button | "Print door QR codes" → P-03, one card per selected unit |
| L08-CHK-SELECT | Checkbox | Row selection, enables bulk QR printing and bulk export |

Arrives from: L03-CRD-OCCUPANCY ("Route to L-08 filtered to vacant units") · L-03 "No data at all" state.

## Empty state (E2)

| Message | Action offered |
|---|---|
| Your properties and units live here. | Add your first unit |

## Open questions

> OPEN: L03-CRD-OCCUPANCY routes here "filtered to vacant units", but L-08 defines no filter control.
> OPEN: "Notice period" chip — nothing in the spec sets a tenancy into notice (see L-12, product.md §15).
> OPEN: "bulk export" — no export button or file format is defined on L-08.
> OPEN: No add-property flow exists. L08-BTN-ADDUNIT asks for "property", but properties are created only in L-02.
> OPEN: Unit numbers must be unique within a property (L-02 rule). Assumed to apply to L08-BTN-ADDUNIT too.
> OPEN: L08-BTN-PRINTQR with no rows selected — behaviour not stated (E2-03 offers "Print door QR codes" from L-06).
> OPEN: Creating a unit creates "its own reporting link" (product.md §15); per §5 "Creates a link and a printable QR for every unit".
