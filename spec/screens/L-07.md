# L-07 · Request detail panel

Source: UI/UX Specification v1.0, Part B. Module M-4 (product.md §6). Assistant: "Maintenance requests" (product.md §11).

## Meta

| | |
|---|---|
| ROUTE | `/maintenance/:requestId` |
| PURPOSE | Everything about one reported problem, and every action needed to close it. |

## Components

| ID | Type | Content and behaviour |
|---|---|---|
| L07-HDR | Panel header | Request number · unit · urgency chip · status dropdown |
| L07-SEC-REPORT | Content block | What the tenant wrote, verbatim, with the date and their name. Never edited. |
| L07-GAL-PHOTOS | Photo strip | Before photos from the tenant; after photos added by the landlord. Tap to enlarge. |
| L07-SEL-CATEGORY | Dropdown | Pre-filled by the assistant, editable. Options: Plumbing · Electrical · Appliance · Structural · Pest · Cleaning · Other |
| L07-FLD-VENDOR | Text field | Vendor name and phone. Remembers previously used vendors as suggestions. |
| L07-FLD-COST | Money field | What it cost. Required to close. |
| L07-CHK-TENANTLIABLE | Checkbox | "Tenant is liable for this cost" — when ticked, offers a payment link instead of absorbing the cost |
| L07-BTN-DISPATCH | Primary button | "Send job to vendor" |
| L07-BTN-UPDATETENANT | Secondary button | "Update the tenant" |
| L07-TML-HISTORY | Timeline | Every status change, message sent and note added |
| L07-BTN-PAYREQUEST † | Button | "Send payment request" — revealed by L07-CHK-TENANTLIABLE |

† ID assigned in conversion.

## Interactions

| Trigger | Result |
|---|---|
| L07-BTN-DISPATCH | Opens S-01 with a vendor-flavoured draft containing: the problem, the unit's address, the tenant's phone and a Maps link. Recipient defaults to the vendor's number, not the tenant's. |
| L07-BTN-UPDATETENANT | Opens S-01 with a status-update draft addressed to the tenant. The draft never mentions cost or vendor rates. |
| L07-CHK-TENANTLIABLE | Reveals a "Send payment request" button that opens S-02 with the cost pre-filled |
| Status set to Done | Validates that a cost or "no cost" is present · prompts to add an after photo · offers to notify the tenant |

## Rules

**Never expose to the tenant:** the vendor's rate, the cost recorded, internal notes, or any other unit. The tenant update draft is built from status and category only.

## Open questions

> OPEN: "Never expose to the tenant … the cost recorded" vs L07-CHK-TENANTLIABLE, which sends the tenant a payment request (S-02) "with the cost pre-filled". Is a cost inside a landlord-sent message allowed?
> OPEN: The tenant-chosen category options (T-01: "Something else") differ from L-07's ("Other").
> OPEN: "Pre-filled by the assistant" — T-01 also says the assistant suggests urgency. L-07 has no field for the suggested urgency; L07-HDR shows a single urgency chip. Which urgency does the chip show (tenant's or assistant's), and is urgency editable here?
> OPEN: Is the tenant's original category overwritten by the assistant's suggestion, or kept?
> OPEN: "The cost recorded … Required to close", but L-06 allows an explicit "no cost". L07-FLD-COST has no "no cost" control.
> OPEN: "internal notes" are mentioned ("note added" on the timeline) but there is no add-note element.
> OPEN: L07-FLD-VENDOR is a single text field for "name and phone". The vendor's phone is needed as the S-01 recipient.
> OPEN: Status dropdown values are assumed to be New · Assigned · In progress · Done (L-06). Does assigning a vendor change the status?
> OPEN: The address in the dispatch draft — the source gives the property address (L02-FLD-PROPADDR); no unit-level address exists.
> OPEN: No tap-to-call element exists here, though product C-5 lists "calling from a maintenance request · calling a vendor".
> OPEN: The add-after-photo control (S-04, max 10) is implied by "prompts to add an after photo" but has no element ID.
> OPEN: "Request number" format — T-02 shows R-0412. Numbering scope (per landlord or global) is not stated.
