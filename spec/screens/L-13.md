# L-13 · Deposit and settlement

Source: UI/UX Specification v1.0, Part B. Module M-8 (product.md §6). Journey stage "6 · Move-out" (product.md §5). Assistant: "Deposit settlement" (product.md §11).

## Meta

| | |
|---|---|
| ROUTE | `/deposits` · `/deposits/:tenantId` |
| PURPOSE | Turn a potential argument into a document. This screen exists to be printed. |

Arrives from: L11-BTN-ENDTENANCY ("routes to L-13 with this tenant selected").

## Components

| ID | Type | Content and behaviour |
|---|---|---|
| L13-TBL-HELD | Data table | Every deposit currently held: unit, tenant, amount, since when. Total at the top. |
| L13-SEC-DEPOSIT | Key-value block | On the settlement page: amount held, date received, agreement reference |
| L13-TBL-DEDUCTIONS | Editable table | Each row: description · reason · amount · photo. Add and remove rows. |
| L13-BTN-FROMREQUESTS | Secondary button | "Pull from repair history" — lists this tenancy's requests with costs and lets the landlord tick the ones to deduct, carrying their photos across |
| L13-SEC-BALANCE | Calculation block | Deposit held − total deductions = refund due. Large, unmissable. |
| L13-BTN-GENERATE | Primary button | "Prepare settlement statement" |
| L13-BTN-PRINT | Secondary button | Opens P-02 |
| L13-BTN-SEND | Secondary button | Opens S-01 with the settlement summary |
| L13-BTN-CLOSE | Primary button | "Mark settled" → confirm → tenancy closes, unit becomes vacant, statement is filed under documents |

## Rules

- A deduction without a written reason cannot be saved. A deduction without a photo shows a warning but is allowed, since not everything is photographable.
- If deductions exceed the deposit, the balance shows as an amount owed by the tenant, in danger colour, and the statement wording changes accordingly.
- Once marked settled, the statement becomes read-only. Corrections require a new statement that references the first.

| Message | Action offered |
|---|---|
| Deposits appear here once you add tenants. | Add tenant |

## Open questions

> OPEN: "statement is filed under documents" + "read-only" vs L14-TBL-DOCS offering "delete" on every uploaded file.
> OPEN: L13-BTN-FROMREQUESTS can pull a repair that the tenant already paid through L07-CHK-TENANTLIABLE's payment request. Nothing prevents deducting it twice.
> OPEN: "Corrections require a new statement that references the first" — no control or flow creates a correcting statement.
> OPEN: L13-BTN-GENERATE "Prepare settlement statement" — the scope says the assistant "Turns the deposit amount, the deductions and their reasons into a written statement". What GENERATE produces (an assistant draft? an editable text?) and where it is shown is not stated.
> OPEN: How the statement wording "changes accordingly" when deductions exceed the deposit is not given.
> OPEN: Does a deduction's description and reason differ? Both are columns; only "reason" is required.
> OPEN: Deposit "date received" — no flow records the deposit being received (product C-1 "deposit at move-in" via UPI).
> OPEN: Two Primary buttons (GENERATE and CLOSE) vs A2 "Maximum one per screen region".
> OPEN: E2 action "Add tenant" — there is no add-tenant control on L-13.
> OPEN: Settling with no deductions, and a refund "due" — no step records that the refund was paid.
